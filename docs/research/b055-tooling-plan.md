# B-055 tooling plan: tsconfig split, coverage, Prettier

Status: research note. No source, test, config, package or CI file was changed,
staged or committed. This note is the only written file.

Scope: the build/split, coverage and formatting half of B-055. The six strict
flags and the curated oxlint config are covered by
[`b055-lint-inventory.md`](b055-lint-inventory.md); they are only cross-checked
here where they interact with the split.

Measured 2026-11-25 at `main` `e5c002a`: Windows x64, Node 26.13.1, npm
10.8.2, TypeScript 7.0.2, Vitest 5.1.1, esbuild 0.28.2, Prettier 3.10.1.
Experiments ran in `<temp>` outside the repo; the temporary coverage provider
was installed into `node_modules`, measured, removed, and the tree restored to
`npm ci` state (verified by directory diff).

Constraint: no runtime behaviour, report byte, public API or package content
change. "Package content" is read as the shipped file set and entry points, not
byte-identical generated JS — see R6.

## 1. Client/server module map

Imports of every `src/**/*.ts` were parsed, and the real browser entry was
bundled with the build script's properties plus `--metafile`. The metafile is
authoritative for the browser graph.

| Module | Browser role | Also server |
| --- | --- | --- |
| `src/render/report-client.ts` | entry; `document`, `window`, `navigator` | no |
| `src/render/client-i18n.ts` | `Intl.NumberFormat`, `Intl.PluralRules` | no |
| `src/render/dom-contract.ts` | attributes/ids, no DOM globals | yes: `html`, `details`, `report`, `trends`, `triage` |
| `src/render/search.ts` | `URL`, `URLSearchParams`, tag expressions | no |
| `@cucumber/tag-expressions` (bundled) | tag parser | no |

`dom-contract.ts` is the only **shared** runtime module. It imports
`UNEXECUTED_HIDE` from `search.ts` and `type { ReportStatus }` from
`src/report/status.ts`; the status import is erased (`import type`, absent from
the metafile), so `status.ts` is shared by type only.

Everything else is **server** (52 of 56 `src/**/*.ts`): `src/*.ts` (CLI, run,
options, output, summary, email, pdf, history, baseline, ci, text, warnings,
validation, stream, attachment, …), `src/input/*`, `src/report/*`,
`src/compat/*`, `src/i18n/catalogs.ts`, and all `src/render/*` except the four
above.

- `src/render` is not a client folder: `details.ts`, `attachments.ts` and
  `ansi.ts` use `Buffer`, `html.ts` uses `node:crypto`; they emit HTML strings.
- `client-bundle.ts`, `print-script.ts` and `styles.ts` are server-side string
  carriers (the first two generated by `scripts/build-*.mjs`) embedded in HTML.

Only `src/pdf.ts` mixes both: `node:module`/`node:path` plus three lines inside
`page.evaluate(...)` that use the browser `document`. That is browser-context
code by design, so the smallest seam is none. A no-DOM server probe
(`lib: ["ES2022"]`) gives exactly 5 errors in 2 files: `pdf.ts` (4) and
`report-client.ts` (1).

## 2. tsconfig split

| File | Role | Change |
| --- | --- | --- |
| `tsconfig.json` | server + test project, base for all others | unchanged |
| `tsconfig.client.json` | browser graph typecheck | new |
| `tsconfig.build.json` | declaration emit for `dist/` | unchanged |
| `tsconfig.compat-cjs.json` | CJS compat emit | unchanged |

`tsconfig.client.json`:

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": { "noEmit": true, "lib": ["ES2022", "DOM"], "types": [] },
  "include": [
    "src/render/report-client.ts",
    "src/render/client-i18n.ts",
    "src/render/dom-contract.ts",
    "src/render/search.ts",
    "src/report/status.ts"
  ]
}
```

`extends` inherits `target: ES2022`, `module/moduleResolution: NodeNext`,
`strict`, `verbatimModuleSyntax`, `skipLibCheck` and the six planned strict
flags. The entry pulls the other four anyway; the list documents the boundary.

| Project | Include | lib | types |
| --- | --- | --- | --- |
| server (`tsconfig.json`) | `src/**/*.ts`, `src/**/*.cts`, `test/**/*.ts`, both configs | `ES2022` + `DOM` | `node` |
| client (`tsconfig.client.json`) | the 5 files above | `ES2022` + `DOM` | `[]` |
| shared | not created | — | — |

**No shared project.** The shared set is `dom-contract.ts` plus type-only
`status.ts`, already in the client program. A no-DOM project cannot work:
`search.ts` uses `URL`/`URLSearchParams`, so `lib: ["ES2022"]` + `types: []`
fails with 4 errors in `search.ts`. Adding DOM makes it identical to the client
project. The server keeps `DOM` because of `pdf.ts`.

**How typecheck runs:** `"typecheck": "tsc --noEmit && tsc --noEmit -p
tsconfig.client.json"`. Measured 1.4 s + 1.1 s. `tsc -b` does work on TS 7.0.2
(a two-project solution with `composite: true`, `noEmit: true` and
`verbatimModuleSyntax` exits 0), but it writes `*.tsbuildinfo` and needs
`tsconfig.json` turned into a solution file, which esbuild and
`tsconfig.build.json` depend on. Two `-p` runs are the smallest complete change.

**Migration cost: zero files.** The client project typechecks green today with
`types: []`, and green with all six planned strict flags (0 errors). No client
module reads `process.env` or imports a server helper. TS 7's `DOM` lib already
covers `NodeList` iteration; TS 5.9 would need `DOM.Iterable` in the client
`lib`, which only matters if the pinned `typescript@^7.0.2` is downgraded.

**Build and esbuild cannot change.**

- `tsconfig.build.json` is untouched and still extends the unchanged
  `tsconfig.json`. `tsc -p tsconfig.build.json --outDir <temp>` emits 56
  `.d.ts`, byte-identical to the 56 in `dist/` (1.2 s).
- esbuild auto-discovers only `tsconfig.json`; it does not read
  `tsconfig.client.json`. Forcing it anyway gives identical bundles: client
  entry SHA-256 `85E6AE0E…` both ways (15,438 bytes, budget 16,000), and
  `src/index.ts` `F4F69AD6…` both ways.

## 3. Coverage

**Provider.** `@vitest/coverage-v8` must match the installed Vitest exactly:
5.1.1 peers `vitest: 5.1.1`. The lockfile resolves Vitest 5.1.1, so pin
`"@vitest/coverage-v8": "5.1.1"` (exact, bump both together). It adds 12
dev-only packages. Practical note: `npm install --no-save --no-package-lock
@vitest/coverage-v8@5.1.1` crashes npm 10.8.2 in arborist
(`Cannot read properties of null (reading 'edgesOut')`); `--legacy-peer-deps`
works and `npm ci` restores. A normal `-D` install with the lockfile was not
tested because it would modify `package.json`.

**Measured** (whole suite: 92 files, 1765 passed, 10 skipped):
`npx vitest run --coverage --coverage.include="src/**/*.ts"
--coverage.reporter=text-summary`

| Scope | Statements | Branches | Functions | Lines |
| --- | --- | --- | --- | --- |
| src, without `report-client.ts` | 94.65 % (4639/4901) | 88.04 % (3772/4284) | 96.86 % (864/892) | 96.05 % (4240/4414) |
| src, with `report-client.ts` | 87.95 % (4639/5274) | 83.34 % (3772/4526) | 92.01 % (864/939) | 89.22 % (4240/4752) |
| Vitest default (adds test helpers) | 94.67 % | 88.02 % | 96.98 % | 96.11 % |

Covered counts were identical across runs. `src/render/report-client.ts` is the
only 0 % file (0/338 lines): the browser entry, never imported by Node tests,
covered by the Playwright suite. Next-lowest after excluding it: `escape.ts`
87.5 % lines / 75.0 % branches, `compat/options.ts` 87.7/85.4, `pdf.ts`
88.6/86.7, `input/legacy.ts` 88.8/78.4.

```ts
coverage: {
  provider: 'v8',
  include: ['src/**/*.ts'],
  exclude: ['src/render/report-client.ts'],
  reporter: ['text-summary'],
  thresholds: { statements: 93, branches: 86, functions: 95, lines: 95 },
}
```

Thresholds are floor minus 1 point, branches minus 2 (the noisiest metric):
96.05→95, 94.65→93, 96.86→95, 88.04→86. `src/**/*.ts` already excludes the
`.cts` shim and there are no `*.d.ts` in `src`; test helpers stay out of scope.
If cross-Node variance appears (CI covers 22/24/26 and Windows), lower all four
by 1 point in a documented follow-up rather than dropping the gate.

**Cost.** Repeated runs on the shared host: plain suite 8.5–19.7 s, with
coverage 11.8–17.7 s. Median increase about 3 s, worst observed about 5 s
(~30–40 %).

## 4. Prettier

`.prettierrc.json`: `{ "singleQuote": true, "printWidth": 80 }`. Everything
else stays Prettier 3.10.1 default (semicolons, `trailingComma: "all"`,
`arrowParens: "always"`, 2 spaces, `endOfLine: "lf"`), matching `.editorconfig`.
Pin exactly (`"prettier": "3.10.1"`) so a minor release cannot reformat the
tree; bump it as a deliberate formatting commit.

Measured tracked files that would change in the scope below: 156 at width 80;
180 at 90; 186 at 100; 196 with double quotes; 187 with `trailingComma: "es5"`.
80 is both the default and the smallest diff — most code is already wrapped
there.

`.prettierignore`:

```text
node_modules/          dist/               coverage/
playwright-report/     blob-report/        test-results/
playwright/.cache/     playwright/.auth/   .openchamber/
.opencode/             .tmp/               .cache/
openspec/              test/fixtures/      docs/comparison/
docs/ui-loop/          package-lock.json   *.tgz  *.png  *.webm
src/render/client-bundle.ts   src/render/styles.ts
src/i18n/catalogs.ts          src/render/report.css
src/render/baseline.css       *.md
```

(One pattern per line in the real file; grouped here for brevity.)

- `client-bundle.ts`, `styles.ts`, `catalogs.ts` are generated and rewritten by
  `npm run assets`, so formatting them creates churn the build reverts.
- `report.css`/`baseline.css` are copied verbatim into `REPORT_CSS`/
  `BASELINE_CSS`; formatting changes every report byte, which B-055 forbids.
- `test/fixtures/` holds inputs and the two committed golden HTML files
  (`render-golden/minimal.html`, `attachments-presentation.html`, compared with
  `toMatchFileSnapshot`); formatting them breaks the golden test.
- `openspec/` is contract history (372 files). `*.md` keeps the first commit
  code-only: docs ship in the tarball, and 44 docs plus 3 root files would
  change. Markdown can follow as its own commit.
- `package-lock.json` is tool-owned.

**Blast radius: 156 tracked files.** `src/` 36 of 56 `.ts` (no generated file,
no CSS; `search.ts` and `print-script.ts` are already clean); `test/` 109 of
129 non-fixture `.ts` (32 helpers, 29 e2e); `scripts/` 7 of 10; `.github/` 3
issue templates; `tsconfig.json` 1. Untouched: 163 fixtures, docs, `openspec/`,
generated TS, CSS, committed PNGs.

**Byte-safety evidence.**

- Formatting all 56 `src/**/*.ts` in a copy, rebuilding the CLI and rendering
  two fixtures gives identical report bytes: legacy minimal `A898B8F4…`,
  German Messages screenshot `FE687570…`.
- The minified client bundle stays `85E6AE0E…` (15,438 bytes) when
  `report-client.ts` is formatted and rebuilt with the repo `tsconfig.json`.
  A build without a tsconfig differs only because esbuild loses
  `target`/`useDefineForClassFields`, not because of formatting.
- Non-minified `dist/index.js` and `dist/cli.js` do change on rebuild from
  formatted sources (+928 / +982 bytes, whitespace and line breaks only, see
  R6).
- `@ts-expect-error` (2) and `oxlint-disable-next-line` (4) directives stay
  directly above their target. There are no inline snapshots.

**Scripts:** `"format:check": "prettier --check ."`, `"format": "prettier
--write ."`. Run `npm run format` once, then `npm run assets` and confirm
`git diff --exit-code src/render/client-bundle.ts`. Optional: add the commit to
`.git-blame-ignore-revs`. Cost: 4.5 s cold through `npx`, ~2–3 s local.

## 5. CI and scripts

```json
"typecheck": "tsc --noEmit && tsc --noEmit -p tsconfig.client.json",
"lint": "oxlint . --max-warnings=0",
"format:check": "prettier --check .",
"format": "prettier --write .",
"test:coverage": "vitest run --coverage",
"check": "npm run i18n:check && npm run assets && npm run typecheck && npm run lint && npm run format:check && npm run build && npm run test:coverage"
```

Plus: delete `passWithNoTests: true` from `vitest.config.ts`, add the coverage
block from section 3, add `prettier` + `@vitest/coverage-v8` to
`devDependencies`.

- `check` keeps its order; the final `npm run test` becomes `test:coverage`
  because `i18n:check` and `assets` already ran at the start and in `build`.
  Whole gate: **+7 to +10 s** (tsc +1.1 s, Prettier +2–4 s, coverage +3–5 s).
- **No workflow edit:** `ci.yml` and `release.yml` only call `npm run check`,
  `build` and `test:e2e`; all four check jobs pick the changes up.
- `--max-warnings=0` is supported by oxlint 1.90 and the current tree exits 0
  with it; it bites once the curated config adds warnings.
- Removing `passWithNoTests` makes `vitest run` and `i18n:check` fail on an
  empty or mistyped include — intended; no CI step relies on a no-test pass.
- `prepublishOnly` runs `check`, so a release also requires a clean format and
  passing thresholds. Dev-only packages do not enter the tarball.

## 6. Risks

| # | Risk | Mitigation |
| --- | --- | --- |
| R1 | The client project only guards its 5 files; a new browser module outside the graph is checked only by the server project. | Anything reached from `report-client.ts` is pulled in automatically; review the list when the entry changes. The metafile is the source of truth. |
| R2 | The server project keeps `DOM`, so it alone would not catch `document` in server code. | Accepted: `pdf.ts` needs DOM legitimately. The client project is the no-Node guard. |
| R3 | Two `tsc` runs in four CI jobs. | +1.1 s per job, ~2.5 s local. No `tsc -b`: it would restructure the config esbuild depends on and write `*.tsbuildinfo`. |
| R4 | Coverage thresholds can flake across Node 22/24/26 or Windows; the provider peer is exact. | 1–2 points headroom; lower by 1 if drift appears. Pin both packages to the same version. |
| R5 | Coverage sees unit tests only; e2e-only code shows 0 %. | `report-client.ts` is excluded, its guarantee stays with Playwright. Decide explicitly for any new e2e-only module. |
| R6 | Rebuilding after formatting changes non-minified `dist/*.js` whitespace (+928/+982 bytes), so the next tarball is not byte-identical to 0.6.1. Report bytes, behaviour, API and shipped file list are unchanged. | Accepted as formatting-only. If byte-stable dist is required, do not rebuild `dist` in the formatting commit; the next release rebuild is the documented point. |
| R7 | A 156-file commit obscures `git blame`. | One isolated commit, never mixed with logic; optional `.git-blame-ignore-revs`. |
| R8 | Formatting generated assets or CSS would change report bytes or be reverted by the build. | Both are ignored; the proof step (`npm run assets` + `git diff --exit-code src/render/client-bundle.ts`) catches a wrong ignore list. |
| R9 | Removing `passWithNoTests` breaks ad-hoc `vitest run <typo>`. | Intended; every package script names a real file or the full glob. |
| R10 | `--max-warnings=0` turns each new warning into a gate failure. | Land the curated config with zero warnings before enabling the flag. |
| R11 | `.prettierignore` drifts when a build script gains an output. | Keep generated paths in one block; review when a build script changes. |
| R12 | The no-lock provider install hit an npm 10.8.2 arborist bug. | Add it as a normal devDependency with the lockfile; fall back to `--legacy-peer-deps` then `npm ci`. |
