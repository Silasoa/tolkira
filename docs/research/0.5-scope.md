# 0.5 scope research

Research note, 2026-11-22. What makes 0.5 "Trust & ship" weightier than the
four shipped slices (metadata links, size diagnostics, Azure/Jenkins/shards CI,
flaky trends), checked against
[`reporting-feature-requests.md`](reporting-feature-requests.md),
[`playwright-oss-comparison.md`](playwright-oss-comparison.md),
[`reporter-compatibility.md`](reporter-compatibility.md), the backlog and a
fresh performance audit.

## Findings

| Candidate | Evidence | Effort | Decision |
| --- | --- | --- | --- |
| Retry evidence (B-043) | Retry/flaky is the second request cluster; Playwright and Allure users ask for first-attempt evidence | M | **Add** as display-only earlier attempts with error/status/duration and one image; no summary/schema change |
| Attachment skip reasons | Attachments are the largest cluster (56 of 395 titles); missing/unreadable files inside roots are silent today | M | **Add** names and reasons, final attempt only; no schema change |
| History window | Allure asks for a configurable run window; `HISTORY_LIMIT` is fixed at 30 | S | **Defer** to `B-044`; no user trigger in the 0.5 cycle |
| Early input-size warning (B-040) | A large input spends the full render before the output-size warning | S | **Defer**; the trigger is a large-input report, not yet present |
| Exact report-byte grouping (B-041) | The exact row is ungrouped beside the MB contributor rows | XS | **Defer**; polish without a user trigger |
| Static all-expanded no-JS (B-042) | Jenkins CSP also blocks inline CSS and `data:` images; a static mode cannot fix that | L | **Defer**; 0.6-sized and does not solve the stock-Jenkins problem |
| CSS minification | Measured ~46 KB -> ~40 KB (13 %) per report | S | **Add** as `report-css-minify`; report size is a product requirement |
| Windows CI | No Windows check job although the maintainer develops there | XS | **Add** as `ci-windows`; real drop-in coverage |
| More hosts (Behat, Reqnroll, Karate) | Producer variants, no new adapter | S each, live | **Defer**; existing matrix covers the supported formats |

## Rejected / held

- A theme gallery, split assets, RTL, trace viewer, screenshot diffing and a
  merge command stay non-goals or trigger-based backlog.
- A flaky summary field, retry history, filters and a retry trend need a schema
  decision and wait for 0.6.
- PDF page identity/tagged PDF, email extras and print page numbers remain
  trigger-based; 0.5 does not claim them.

## Drop-in coverage

- Added: Windows `npm run check` in CI.
- Re-run in this cycle: Seed-Test 0.5 tarball, Cucumber-JS legacy/Messages,
  Playwright movies-app, Spring PetClinic, Cucumber-JVM.
- Not live-tested: Jenkins/Azure commands, sharded upload/download, Behat/
  Reqnroll/Karate. Their recipes stay labelled as documented, not live-tested.

## Performance

The audit found the render pipeline linear at 1,000/5,000 scenarios, no
unbounded path and no module split worth the churn. The only safe size win is
CSS minification; the attachment grouping micro-optimisation is deferred until a
real large-attachment case appears. The report remains one self-contained file.

## Outcome

0.5 adds two user-facing diagnostics (named attachment skips, earlier-attempt
evidence), a real Windows gate and a smaller report. The summary schema stays
version 2, history stays version 1, and no dependency is added.
