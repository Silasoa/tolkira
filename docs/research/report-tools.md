# Test-report tools: what users value, and what Tolkira should borrow

Research note, 2026-11-03. Sources are primary: npm registry, GitHub API and
issue threads, official docs. Download counts are npm last-30-days at access
time. Quotes are verbatim. No production code was changed.

## 1. Table stakes

1. **Summary**: pass/fail/skip counts, pass rate, total duration.
2. **Scenario and step detail**: Gherkin structure, hooks, error, stack trace.
3. **Attachments**: screenshots inline or lightbox, video/audio/text, download.
4. **Search and filters**: free text plus status, tag, feature; failed-first.
5. **Metadata**: browser, OS, app version, branch, commit, CI link.
6. **Durations**: total, feature, scenario, slowest tests.
7. **Retries**: one row per scenario, attempts expandable, final status.
8. **Portable artifact**: single file or folder, opens offline, no CDN.
9. **CI contract**: stable path plus JSON/JUnit output.
10. **Safe rendering**: escaping, attachment sanitising, no secret leakage.

Allure's [feature list](https://allurereport.org/docs/features-overview/) sets
the mature bar: steps, attachments, filtering, environments, stability,
history/retries, quality gates, timeline.

## 2. What users praise most

- **One simple artifact.** cucumber-html-reporter: “The report speaks for
  itself” ([#71](https://github.com/gkushang/cucumber-html-reporter/issues/71))
  and “big thanks for only useful Cucumber JS HTML reporter!”
  ([#147](https://github.com/gkushang/cucumber-html-reporter/issues/147)).
  Mochawesome: “This report looks ace”
  ([#26](https://github.com/adamgruber/mochawesome/issues/26)).
- **Dashboard and branding.** multiple-cucumber-html-reporter: “I love this
  report” ([#1](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/1))
  and “Found reports generated by this project really cool”
  ([#24](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/24)).
- **Debug context.** Playwright: “fantastic features for debugging (html
  testresults, trace.zip)”
  ([#16542](https://github.com/microsoft/playwright/issues/16542)). Cypress sells
  Test Replay as time travel through DOM, network and console.
- **History and flaky detection.** Allure makes history first-class; ReportPortal,
  Buildkite Test Engine and Trunk lead with flaky detection and trends.
- **CI integration.** ReportPortal's Jira/Slack integrations and Cypress's PR
  comments/status checks are core value, not extras.

Direct praise is plentiful for small OSS reporters; enterprise praise is inferred
from feature investment and adoption, not quotes.

## 3. What users complain about most

- **Size and rendering cost.** Official formatter: “Our 423 scenarios produce an
  html report file of 314MB”
  ([#62](https://github.com/cucumber/html-formatter/issues/62)). Jest: “~25K
  tests … rendering of the HTML report is (unsurprisingly!) slow”
  ([#113](https://github.com/Hazyzh/jest-html-reporters/issues/113)); heavy DOM
  makes large suites “sluggish”
  ([#232](https://github.com/Hazyzh/jest-html-reporters/issues/232)).
- **Not portable.** “It would be a lot nicer to have the report as a single HTML
  file and have all the assets and subpages integrated inside”
  ([MCHR #190](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/190);
  maintainer says “planned”, June 2026). Mochawesome users once had to “zip the
  report up to move it around”
  ([#26](https://github.com/adamgruber/mochawesome/issues/26)); Jest split
  reports broke S3 uploads
  ([#184](https://github.com/Hazyzh/jest-html-reporters/issues/184)).
- **Missing metadata.** Cucumber formatter
  [#106](https://github.com/cucumber/html-formatter/issues/106); Playwright
  [#31415](https://github.com/microsoft/playwright/issues/31415),
  [#35178](https://github.com/microsoft/playwright/issues/35178).
- **Server/folder friction.** Allure's default is “not one file, but rather a
  directory … use the `allure open` command”
  ([docs](https://allurereport.org/docs/v3/view-report/)). Playwright reports are
  a folder served as a page; users struggled with Azure DevOps
  ([#16542](https://github.com/microsoft/playwright/issues/16542)) and Jenkins
  ([#10274](https://github.com/microsoft/playwright/issues/10274)).
- **Telemetry and upgrade risk.** Allure 3 users report Google Analytics
  generation is no longer configurable
  ([#476](https://github.com/allure-framework/allure3/issues/476), open, 10
  reactions); Allure 2 sent GA by default with `ALLURE_NO_ANALYTICS=true`
  ([Analytics.md](https://github.com/allure-framework/allure2/blob/main/Analytics.md)).
  Allure broke after a minor upgrade
  ([#571](https://github.com/allure-framework/allure3/issues/571)); MCHR
  regressed on assets in 3.9.x
  ([#413](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/413)).
- **Maintenance/dependency rot.** cucumber-html-reporter: 92 open issues, no
  release since October 2024, open `uuid`/`semver` reports
  ([#256](https://github.com/gkushang/cucumber-html-reporter/issues/256),
  [#297](https://github.com/gkushang/cucumber-html-reporter/issues/297)).
- **UX noise.** “By default only failed/pending tests should be visible … you
  have to do a lot of scrolling”
  ([#147](https://github.com/gkushang/cucumber-html-reporter/issues/147));
  same in [#154](https://github.com/gkushang/cucumber-html-reporter/issues/154).
- **Security.** Unescaped scenario names executed HTML
  ([#52](https://github.com/gkushang/cucumber-html-reporter/issues/52));
  Playwright users asked to stop logging password values
  ([#35848](https://github.com/microsoft/playwright/issues/35848)).

## 4. Most-requested missing features

- **Messages/current Cucumber support** — old reporter's top gap
  ([#202](https://github.com/gkushang/cucumber-html-reporter/issues/202),
  [#244](https://github.com/gkushang/cucumber-html-reporter/issues/244)).
  MCHR now supports Messages, so this gap is closing.
- **Single-file embedding** — [MCHR #190](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/190);
  Mochawesome and Jest later added inline/single-file options.
- **Large/external attachments** — “images and videos … stored in the known
  folder path and referenced by the report”
  ([Cucumber #281](https://github.com/cucumber/html-formatter/issues/281), open).
- **Metadata** — [Cucumber #106](https://github.com/cucumber/html-formatter/issues/106),
  Playwright [#31415](https://github.com/microsoft/playwright/issues/31415).
- **Per-scenario duration** — “I'm interested to see duration of each
  test/scenario” ([Cucumber #375](https://github.com/cucumber/html-formatter/issues/375), open).
- **Hide unrun/excluded scenarios** — [Cucumber #49](https://github.com/cucumber/html-formatter/issues/49),
  [#61](https://github.com/cucumber/html-formatter/issues/61).
- **Multiple attachments, hide hooks, themes** — cucumber-html-reporter
  [#84](https://github.com/gkushang/cucumber-html-reporter/issues/84),
  [#228](https://github.com/gkushang/cucumber-html-reporter/issues/228),
  [#107](https://github.com/gkushang/cucumber-html-reporter/issues/107).
- **Retry-aware counts** — reruns counted as extra tests
  ([MCHR #221](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/221)).
- **Merge/shard and history** — Playwright solved sharding with blob reports
  ([#10437](https://github.com/microsoft/playwright/issues/10437)); Mochawesome
  needed external merge ([#172](https://github.com/adamgruber/mochawesome/issues/172));
  Jest append mode is open
  ([#280](https://github.com/Hazyzh/jest-html-reporters/issues/280)); Allure
  history ([#370](https://github.com/allure-framework/allure3/issues/370)).
- **ReportPortal sharing** — public dashboards
  ([#2](https://github.com/reportportal/reportportal/issues/2), open since 2016),
  video ([#117](https://github.com/reportportal/reportportal/issues/117)),
  embeds ([#396](https://github.com/reportportal/reportportal/issues/396)).

## 5. Fit for Tolkira

| Tool | Fit | Why |
| --- | --- | --- |
| Official Cucumber formatter | **v0.1 parity; later history** | Closest peer: Messages, one file, attachments, search. Gaps: metadata, per-scenario duration, history, huge-report size. |
| multiple-cucumber-html-reporter | **later dashboard/trends** | Messages, dark mode, emailable report, multi-run. Folder-first; single-file still planned. Too heavy for v0.1. |
| Allure 3 | **later history/retries; avoid defaults** | Best-in-class history/stability/quality gates. Single-file exists but has caveats. Default folder/server, plugins and GA conflict. |
| ReportPortal | **Avoid** | Server + DB + queue + MinIO, ML triage, RBAC. Direct conflict with one file, no server, no telemetry. |
| Playwright HTML | **Borrow attachment/merge ideas** | Folder + server, trace viewer, blob sharding, `attachmentsBaseURL`, `doNotInlineAssets`. Delivery model conflicts. |
| Cypress Cloud/Test Replay | **Avoid** | Cloud upload, DOM/network replay, flaky analytics. Privacy and offline conflict. |
| Mochawesome | **Borrow summary/context UX** | Clean offline report, charts, inline test code, filters, inline-assets option. Folder by default. |
| Jest HTML reporters | **Borrow lightweight single-file** | Summary-first, attachments, console logs. Large-suite DOM cost is a warning. |
| TestRail | **Avoid** | Test management, traceability, audit dashboards. Hosted/self-hosted service, no portable report. |
| Buildkite/Trunk | **Borrow flaky metrics only** | Flaky detection, quarantine, slowest tests. Requires uploading results; use local history instead. |

**Positioning corrections.** PRODUCT.md says Allure 3 is “not a single
embeddable HTML file” and MCHR is “legacy JSON only”. Both are outdated:
Allure's Awesome plugin supports `--single-file`, and MCHR 4.x ingests Messages.
Single-file alone is no longer a differentiator. Tolkira's wedge is the
combination: Cucumber-native legacy **and** Messages, one small file, no
telemetry, no server, embeddable, plus an agent-readable summary.

## 6. Recommendations

**Five things to add**

1. **Failed-only preset plus “copy failure”.** One click filters to failures and
   copies scenario, step, error and screenshot reference. Evidence: repeated
   failed-first requests ([#147](https://github.com/gkushang/cucumber-html-reporter/issues/147),
   [#154](https://github.com/gkushang/cucumber-html-reporter/issues/154)).
2. **Retry-aware scenario rows.** Group attempts under one scenario, show final
   status and attempt count, exclude superseded attempts from totals. Evidence:
   [MCHR #221](https://github.com/WasiqB/multiple-cucumber-html-reporter/issues/221).
3. **Optional local history file.** `--history history.json` with pass rate, new
   failures, fixed and flaky counts, shown as a sparkline. Allure 3 proves the
   model with one JSONL file
   ([docs](https://allurereport.org/docs/history-and-retries/)); no server needed.
4. **Slowest scenarios/features panel.** Reuse existing durations to show the
   top 10 slowest and outliers in Analysis. Evidence: Buildkite Test Engine and
   Allure performance metrics.
5. **Screenshot lightbox/gallery with zoom and download.** Screenshots are the
   first-class promise; inline `<img>` alone makes failure inspection harder.
   Evidence: Playwright/Allure attachment UX.

**Five things to avoid**

1. **A built-in server, live watch or report daemon.** Allure `watch`/`open`,
   Playwright `show-report`, ReportPortal. Breaks the one-file promise.
2. **Telemetry or analytics.** Allure's GA history and the open request to
   disable it ([#476](https://github.com/allure-framework/allure3/issues/476))
   show how quickly this erodes trust.
3. **Test management, traceability or audit workflows.** TestRail's ground;
   requires accounts/server and is out of scope.
4. **ML failure triage.** ReportPortal's analyzer needs uploaded history and a
   server; conflicts with privacy and non-goals.
5. **A plugin marketplace or DOM/trace replay.** Allure's plugin system and
   Cypress Test Replay are deep moats, but add surface area Tolkira does not want.
