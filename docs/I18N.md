# Localisation

Tolkira renders the report shell, the optional email summary and the opt-in PDF in
English (`en`)
or German (`de`). The locale is chosen per report with `--locale <tag>` or the
render API; one report carries one locale, and there is no in-report switcher.
The JSON summary, CI text and CLI output stay English. This page is the contract
for translators, reviewers and agents.

## Usage

```shell
tolkira test-results/ --out report.html --locale de
tolkira test-results/ --out report.html --locale de-AT
tolkira test-results/ --email email.html --locale de
tolkira test-results/ --pdf report.pdf --locale de
```

`--locale` requires `--out`, `--pdf` or `--email`. An empty or unknown tag exits
2 and names the supported locales. Matching is exact first, then by primary
subtag: `de-AT` uses the German catalog and records `lang="de-AT"`. The default
is `en`; there is no host, environment or browser detection. The PDF follows the
report locale; no PDF-specific catalog key exists.

```ts
await generateReport(inputs, { locale: 'de' });
await renderReport(inputs, { locale: 'de' });
new CucumberHtmlStream({ locale: 'de' });
```

`RenderOptions.locale` is optional; `de-AT` keeps its regional tag for
`<html lang>` while using the `de` catalog. Unknown API locales throw.
`renderEmail(summary, { locale })` uses the same resolution and throws on an
unsupported tag.

## Catalogs

| File | Shape |
| --- | --- |
| `src/i18n/locales/en.json` | `{ "<key>": { "message": "...", "description": "..." } }` |
| `src/i18n/locales/de.json` | `{ "<key>": "..." }` |

- One flat file per locale, dotted keys, sorted with the default
  `Array.prototype.sort()`. The file name is the locale tag; the generator and
  `npm run i18n:check` derive the tag from it.
- English is the source of truth and carries a non-empty description per key.
  Target catalogs are value-only and must stay in key parity.
- Messages are full sentences with `{placeholders}`, not concatenated
  fragments. Use `{count, plural, one {...} other {...}}` for counts.
- `src/i18n/catalogs.ts` is generated by `scripts/build-i18n.mjs` and committed;
  never edit it by hand. `npm run assets` regenerates it. Its public type is a
  `MessageKey` union plus `Record<MessageKey, string>` catalog maps, so the
  emitted `catalogs.d.ts` does not repeat every message as a literal type.
- `npm run i18n:check` compares the generated module with the JSON sources and
  validates key parity, placeholders, active plural categories per target (each
  target tag gets its own `Intl.PluralRules`), `other`, non-empty values, sorted
  keys and the absence of HTML/`select` syntax. It also rejects ASCII double
  quotes, messages over 2000 characters and `=N` plural branches. It runs before
  `assets` in `npm run check` and `npm test`, so a stale module fails.

### Supported syntax

| Syntax | Example |
| --- | --- |
| Placeholder | `Hallo {name}` |
| Plural | `{count, plural, one {# Datei} other {# Dateien}}` |
| `#` in a plural | `#` renders the count; English keeps it raw, other locales use `Intl.NumberFormat` |
| All plural categories | The server and the client support every category returned by `Intl.PluralRules` (`one`, `few`, `many`, `other`, and so on); an absent category uses `other` |
| Numeric parameters | `{count}` and `#` are locale-formatted in every visible count; English report output stays raw, the email groups digits |

Not supported: `select`, nested plural/select, HTML (`<`/`>`), ASCII double
quotes (use typographic quotes such as `„…“`), messages over 2000 characters,
`=N` plural branches, unbalanced braces and empty placeholders. The catalog
check rejects all of these except a stray `}`, which only the renderer rejects.

### Adding a locale

1. Copy `en.json` to `<tag>.json`, where the file name is the locale tag, for
   example `fr.json` or `de-AT.json`.
2. Translate every `message`; keep placeholders and `#` unchanged, use
   typographic quotes, stay under 2000 characters and do not add `=N`
   branches. Sort the keys and remove the descriptions from the new file.
3. Run `npm run assets`. `scripts/build-i18n.mjs` discovers every
   `src/i18n/locales/*.json`, derives each tag from its file name, emits one
   `Record<MessageKey, string>` catalog per locale and adds it to `catalogs`; no
   manual `SUPPORTED_LOCALES` or `CATALOGS` edit is needed. `npm run i18n:check`
   validates each target with its own `Intl.PluralRules` tag.
4. Only for an RTL locale, add its tag to `DIRECTIONS` in
   `src/render/i18n.ts`; the default is `ltr`.
5. Add or update tests and docs, including the CLI usage line that names the
   supported locales and any test that asserts that list. Then run
   `npm run i18n:check`, the focused render tests, `npm run check` and the
   browser gate at 320, 390, 768, 1024 and 1440 px plus 320 px at 200 % text
   zoom.

A regional variant is a separate JSON file whose tag matches the region, such as
`de-AT.json`; without one, `de-AT` falls back to `de`. If a target file is
missing an English key or contains an extra key, the generator and
`npm run i18n:check` fail with the file and key instead of dropping it.

## Fallback and formatting

- On the server, a missing key falls back to English, then to the key itself.
- A missing plural category uses `other`.
- All visible report counts are locale-formatted, on the server and in the
  client; English report digits stay raw. Other locales use `Intl.NumberFormat`,
  so German decimals use a comma and percentages include the locale's no-break
  space. The report's English percentages, durations and dates keep the previous
  output; non-English durations keep their unit labels and use a locale decimal
  separator. The email groups English digits (`8,509 bytes`) and uses a short
  human duration form (`12 ms`, `12.3 s`, `1 min 5 s`, `1 h 2 min`), because it
  is read outside the report shell.
- German dates are `DD.MM.YYYY, HH:MM UTC`; that order is German, not a rule
  for every non-English locale. The date parts come from
  `Intl.DateTimeFormat` with `timeZone: 'UTC'`. `de` is currently the only
  non-English catalog; a new locale needs its own date order and tests.
- A complete value-and-unit message may be joined with punctuation (the
  exact/rounded size pair, or the `details.inputFiles` plural followed by ` · `
  and `sizeLabel`) because the join carries no translatable word order, so no
  new catalog key is needed. For `format.megabytes` and percentages, a number
  and its unit are kept together with a non-breaking space in code, not in the
  catalog; the `format.bytes` row uses a normal space. ILA accepted this
  composition.
- `format.bytes` takes the raw numeric byte count, never a pre-formatted
  string: the formatter applies locale grouping (English keeps the raw digits)
  and a target catalog's plural branch selects its category from the number.
  `count` is not locale-formatted on input. The email path also passes the raw
  number and groups the digits afterwards. `format.megabytes` still receives an
  `Intl` one-decimal string: the caller rounds the byte count to one decimal for
  display and passes that formatted string, so the reason is precision, not a
  missing numeric value. A plural branch on `format.megabytes` is not supported
  and would hit the same `Number("1,2")` NaN throw; B-045's deferred work covers
  it.
- Counts used for sorting, `data-*` attributes, URL state and the summary stay
  numeric.
- The report always embeds the active `client.*` messages as an inert JSON
  block. The client uses that block as its only source: the old English fallback
  map is gone, and if the block or a key is missing the client shows the key
  itself. The client supports every `Intl.PluralRules` category and formats `#`
  and numeric parameters; the browser bundle contains no non-English catalog.

## What is not translated

Test data renders verbatim in every locale: feature, scenario, rule and step
names, Gherkin keywords, tags, doc strings, data tables, error text, attachment
content and names, metadata values and URIs. So do machine identifiers: status
ids, `data-*` values, CSS classes, URL parameters, JSON keys and values, CLI
commands, exit codes and the default title `Tolkira report` (it feeds the
history id). The CLI CI formatter, CLI usage/errors and the JSON summary stay
English.

Synthetic report labels such as `Feature:`, `Scenario:`, `Attempt:`, `Started:`,
`Rule:` and `Steps` are chrome and are translated. Clipboard labels are
translated; the copied names and text are not.

## Baseline labels

The baseline panel and row badges reuse the report translator and `status.*`
labels. The JSON keys, `change` values and the Markdown CI line stay English.

| Key | German |
| --- | --- |
| `baseline.heading` | `Vergleich mit Baseline` |
| `baseline.status` | `Baseline-Status: {status}` |
| `baseline.newFailures` | `{count, plural, one {Neuer Fehler} other {Neue Fehler}}` |
| `baseline.fixed` | `Behoben` |
| `baseline.stillFailing` | `Weiterhin fehlgeschlagen` |
| `baseline.notInThisRun` | `Nicht in diesem Lauf` |
| `baseline.ambiguous` | `{count, plural, one {Mehrdeutige Gruppe} other {Mehrdeutige Gruppen}}` |
| `baseline.more` | `{count, plural, one {# weiteres Szenario steht in der JSON-Zusammenfassung; siehe --json.} other {# weitere Szenarien stehen in der JSON-Zusammenfassung; siehe --json.}}` |
| `baseline.moreCapped` | `{count, plural, one {# weiteres Szenario steht in der JSON-Zusammenfassung von {total} (bis zu {cap});} other {# weitere Szenarien stehen in der JSON-Zusammenfassung von {total} (bis zu {cap});}} {missing, plural, one {# wird nur gezählt. Siehe --json.} other {# werden nur gezählt. Siehe --json.}}` |
| `baseline.badgeNewFailure` | `Neuer Fehler` |
| `baseline.badgeFixed` | `Behoben` |

The count labels are ICU plurals with `{count}`; the number stays in the
surrounding `<b>` and the badge keys stay singular. German shows `1 Neuer
Fehler` / `2 Neue Fehler` and `1 Mehrdeutige Gruppe` / `2 Mehrdeutige Gruppen`.
`baseline.more` covers up to 50 absent rows; `baseline.moreCapped` states the
JSON cap when the total is above 50. Baseline feature names, scenario names and
example coordinates are stripped of controls and bidi marks, whitespace-collapsed
and escaped; the display URI is reduced like a current-run URI.

## Email labels

The email summary is a second localized surface with its own `email.*` keys. It
reuses `status.*`, `report.scenarioWithResults`, `report.featureCount`,
`report.stepCount`, `report.attachmentCount`, `format.bytes`,
`format.noAttempts` and `format.emptyRatio`, sets
`<html lang>` and `dir`, and formats its counts, percentages and `Generated` date
with the same translator. Counts use the locale's number format, and durations
use the email-local human form in every locale. Email test data, the optional
title and the report basename render verbatim. The email is server-rendered, so it
does not use the client `client.*` block.

| Key | German |
| --- | --- |
| `email.title` | `{title} — {status}` |
| `email.generated` | `Erstellt: {date}` |
| `email.passRate` | `Erfolgsquote` |
| `email.passRateNote` | `Die Erfolgsquote zählt nur ausgeführte (nicht übersprungene) Szenarien.` |
| `email.features` | `Features` |
| `email.steps` | `Schritte` |
| `email.duration` | `Dauer` |
| `email.attachments` | `Anhänge im Lauf` |
| `email.unexecuted` | `{count} nicht ausgeführt` |
| `email.failedTitle` | `Fehlgeschlagene Szenarien` |
| `email.moreFailures` | `{count, plural, one {# weiteres fehlgeschlagenes Szenario} other {# weitere fehlgeschlagene Szenarien}}` |
| `email.noFailures` | `Keine fehlgeschlagenen Szenarien.` |
| `email.noFailuresStatus` | `Keine fehlgeschlagenen Szenarien. Laufstatus: {status}.` |
| `email.empty` | `Keine Szenarien in diesem Lauf.` |
| `email.reportNote` | `Vollständiger Bericht: {name}. Bitte separat anhängen oder teilen.` |
| `email.reportMissing` | `Es ist kein vollständiger Bericht angehängt.` |
| `email.footer` | `Erstellt von Tolkira. Eine Datei. Keine Netzwerkanfragen. Kein Tracking.` |

The report note is recipient-facing and must stay fully German. A guard test
fails if the German output falls back to the English `Full report` label or
mixes English copy into the note; the standalone note uses
`email.reportMissing`, not a CLI instruction to run `--out`.

The PDF adds no catalog keys. It prints the report HTML with the resolved locale,
so its labels, counts, percentages, durations and dates come from the report
catalog and translator. `--pdf` therefore counts as a locale target in the CLI
guard.

`flaky` is a technical term in both catalogs (`report.flakySummary`,
`report.flakyBadge`, `trends.flaky`); the German report keeps it untranslated.
`Flaky share` is `Flaky-Anteil` (`trends.flakyShare`), a below-minimum share is
`&lt;` plus the formatted percentage (`trends.flakyShareBelow`), and
`trends.flakyNote` explains the tag-or-retry proxy. `@flaky` test tags render
verbatim, are matched lowercase and exactly, and are inherited, so a feature,
rule or outline tag can badge and count every affected row.

The address form is impersonal; avoid `du` and `Sie`. The full
`Fehlgeschlagen` chip is used and wraps; there is no short form. `de` is the
generic catalog and `de-AT` uses it. Final copy also uses `Laufzeit` for the
runtime value, `Lauf-Hooks` for run-level hooks in the test-time notes,
`Aufgezeichnet am` for the recorded-at column, `Basisverzeichnisse` for the
allowed roots and `Fehlerdetails kopieren` for the copy-failure action. The
attachment notice and the Details pass-rate note are full sentences; the German
`triage.moreInReport` has `one`/`other` branches and the German `triage.lead`
agrees its verb with the need count, not the total.

## Agent checklist

1. Read this guide and the active OpenSpec change.
2. Find the key with `rg '"' src/i18n/locales/en.json`, or narrow by prefix with
   `rg '"client\.'` / `rg '"report\.'` or another area name.
3. Edit only that key in `en.json` and every target catalog; keep placeholders
   and `#` identical. Use typographic quotes, keep the message below 2000
   characters and do not add `=N` branches.
4. Add or update the English description when the meaning changes.
5. Run `npm run i18n:check` and the focused Vitest suites.
6. Run `npm run check`; for report changes also run the browser gate.
7. Check the longest German string at 320 px and 200 % text zoom.

Do not edit `src/i18n/catalogs.ts`, translate test data, add detection, or add a
non-English catalog to the client bundle. The report always embeds only the
active `client.*` messages as an inert, JSON-escaped data block; the client
formatter lives in `src/render/client-i18n.ts`.
