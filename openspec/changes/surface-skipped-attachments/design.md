# Design

## Context

The adapter already skips path attachments outside the input file's folder and
the working directory (`resolveAttachmentPath` → `readAttachment`). The report
does not know about the skip. The decision is how to count the cause precisely
without changing the summary or reading outside the roots.

## Data flow

Playwright JSON → `src/input/playwright.ts` (classified attachment outcomes) →
`src/input/load.ts` (`LoadedInput.skippedAttachments`) → `src/index.ts`
(`generateReport` sums and passes the count) → `src/render/html.ts` (shared
notice and footer) and `src/cli.ts` (stderr). This follows ADR 0001 (hybrid
report engine), ADR 0004 (normalize to Messages) and ADR 0005 (server-rendered
shell).

## Counter

`readAttachment` is the wrong place: a relative path has up to two candidates
and only an all-outside result is a skip. Add a classification step in
`resolveAttachmentPath`:

```
let outside = 0;
let inside = 0;
for (const candidate of candidates) {
  const info = await lstat(candidate).catch(() => undefined);
  if (!info || info.isSymbolicLink() || !info.isFile()) continue;
  const target = await realpath(candidate).catch(() => undefined);
  if (!target) continue;
  if (!context.roots.some((root) => isInside(root, target))) {
    outside += 1;
    continue;
  }
  inside += 1;
  const attachment = await readAttachment(candidate, context);
  if (attachment) return attachment;
}
if (outside > 0 && inside === 0) context.skippedAttachments += 1;
```

`readAttachment` keeps its own lstat/realpath/root check; the pre-check only
classifies, and a swap between the two can only cause a false negative, never a
read outside the roots. Inline bodies, URL/UNC paths, trace zips and earlier
attempts never reach this code. A missing candidate or a failed `realpath` is
ignored (not a root skip).

## Transport

- `parsePlaywrightJson` returns `{ envelopes, skippedAttachments }`.
- `LoadedInput` gains `skippedAttachments` (0 for non-Playwright inputs).
- `generateReport` sums the groups once (the content hash already removed
  duplicate files before parsing) and passes the total to `renderHtml`.
- `GeneratedReport` gains `skippedAttachments` (additive public API).
- `src/warnings.ts` owns the copy:

```
1 path attachment was skipped: it is outside the allowed roots (its input file's
folder and Tolkira's working directory). The report may be missing screenshots
or files.

N path attachments were skipped: they are outside the allowed roots (each input
file's folder and Tolkira's working directory). The report may be missing
screenshots or files.
```

## Rendering

- `renderHtml` inserts one `.noticeShell` wrapper after the screen-reader live
  region and before both tab panels. The wrapper mirrors the shell metrics
  (`max-width: 1320px`, centred, `2rem` side padding, `1.25rem` at 900 px and
  `1rem` at 560 px, no bottom padding) so the notice aligns with `.runHead` at
  every width. Inside it, `<div class="attachmentWarning" role="note">` holds the
  escaped text; no path is interpolated.
- `.attachmentWarning` uses the existing dark-aware `--pending` and
  `--pending-soft` tokens (border, soft background, warning left edge) and wraps
  anywhere. No dark-block override is needed.
- The footer's last sentence becomes neutral for every report:
  `Attachments are embedded when available.` The `Generated by Tolkira. Single
  file. No network requests.` part stays. This removes the false “Screenshots
  are embedded.” claim for missing files, which this change does not count. The
  notice carries the outside-root detail.
- CLI: inside the `if (output)` branch, after `generateReport` and the file
  write, if the count is above zero,
  `io.stderr('tolkira: warning: ' + attachmentWarning(count) + ' ' + ATTACHMENT_HINT + '\n')`.
- The compat shim pushes `attachmentWarning(count) + ' ' + ATTACHMENT_HINT` into
  its existing `warnings` array (`compat/cucumber-html-reporter.ts`), so drop-in
  callers see the notice and the same hint.

## Alternatives considered

- **Add a `warnings` array to summary v2.** Changes the stable summary shape and
  every consumer; rejected, recorded as a backlog decision with a trigger.
- **Count inside `readAttachment`.** Double-counts relative candidates and
  confuses missing files with outside-root files; rejected.
- **Emit the warning only in the Details tab.** Users may never open Details;
  the shared shell is safer.
- **Name the absolute root.** Leaks local paths into a shared report; the role
  description is enough.

## Risks

- A false count if the pre-check and `readAttachment` disagree at the edges; the
  tests cover the cwd fallback, missing, symlink, URL/UNC and inline cases.
- The inlined stylesheet changes every report's bytes; the contract allows a
  stylesheet-only diff and a clean report has no notice markup.
- `GeneratedReport` gains a field; additive and documented.
- Archive order is independent of `clarify-run-presentation`, but both touch
  `input-formats`.
