## Pinned contract

### API

`renderEmail(summary: ReportSummary, options?: EmailOptions): string` in
`src/email.ts`, exported from `src/index.ts`.

```ts
interface EmailOptions {
  title?: string;      // default "Tolkira report", used verbatim after escaping
  locale?: string;     // default "en"; resolved by createTranslator/resolveLocale
  reportName?: string; // basename only in the note; a path is reduced to basename
  accent?: string;     // validated with ACCENT_PATTERN; invalid values are ignored
  now?: Date;          // default new Date(); labelled "Generated"
}
```

No logo option, no file or network access. `renderEmail` writes nothing.
The CLI and this API return identical HTML for the same summary/options/clock.

### Document and template

- Starts `<!doctype html>`; `<html lang="<tag>" dir="ltr">`, UTF-8 meta,
  `<title>` and one `<h1>` containing `{title} — {status}` (em dash).
- 600 px table layout with inline styles: `max-width:600px` and `width:100%`,
  no fixed `width="600"`. A small `<style>` block may carry the mobile and
  forced-colour fallback.
- Status colours are inline. A valid accent appears as a border
  (`border… #123456`); an invalid/hostile accent is ignored and leaves no
  `url(`, `javascript:` or other unvalidated style input in the output.
- No `<script>`, `<img>`, `<picture>`, `<link>`, `<iframe>`, `<object>`,
  `<embed>`, `<a href>`, `href=`, `@import`, `url(`, `http(s)://`, `ftp://`,
  inline `on…=` handler, hidden preheader, `mso-hide`, or `display:none`.
- The generated date uses the translator and the visible label `Generated:`.
- The standard summary stays under 100 KB (tested with 400 failures).

### Metrics and states

- Attempted pass rate: `passRate(summary.counts.scenarios)` plus
  `t.percent`; `format.noAttempts` when zero attempts, `format.emptyRatio`
  when there are no scenarios.
- Every non-zero scenario status is shown with its `status.*` label; the
  unexecuted count uses `email.unexecuted`.
- Total is labelled with `report.scenarioWithResults`; features, steps,
  duration, inline attachment count and raw byte count are shown.
- Failed list: at most five failed scenarios, each with feature, scenario,
  status and duration, no step bodies, plus `email.moreFailures` for the rest.
- No failed scenarios: `email.noFailures` for a passed run;
  `email.noFailuresStatus` for pending/undefined/unknown, never “successful”.
- Empty run: `email.empty` and the empty ratio.
- With `reportName`: note names the basename only and says attach or share.
  Without: `email.reportMissing` and `--out`, no `Full report:`.
- Test data and the default title stay verbatim after HTML escaping.

### CLI

- `--email <file>` is an output: alone, with `--out`, with `--json`, with
  `--ci`, or combined. Empty path exits 2. At least one input is required.
- `--locale` is accepted with `--out` or `--email`; with only `--json`/`--ci`
  it remains a usage error. JSON/CI text stays English.
- Collisions with an input, the logo, `--out`, `--ci-out` or `--history` exit
  2 and write nothing (case-aware via `samePath`).
- Write order: report, email, history, `--ci-out`, stdout.
- Email write failure: exit 1, stderr names the target path and never `.tmp`,
  the report stays, history/`--ci-out`/JSON/CI stdout are skipped and no temp
  file remains.
- With free stdout: `Report written to <path>` then
  `Email written to <path>`; standalone prints only the email line.
  With `--json`/`--ci` on stdout, the machine bytes are unchanged and no email
  line is added. With `--ci-out`, stdout is free, so the email line is printed.
- Report bytes and JSON/CI bytes are unchanged by the additional email.
- Help lists `--email <file>` and the rule
  `Without --out, --json, --ci or --email`.

## Contract correction (2026-11-20)

`test/e2e/email.spec.ts` originally asserted the English literal `Full report`
inside the German email. That contradicted the copy contract above, which
requires native German values with identical placeholders, and forced a
mixed-language `email.reportNote`. The assertion was corrected to the native
label, without weakening the check:

- from `await expect(body).toContainText('Full report');`
- to `await expect(body).toContainText('Vollständiger Bericht');`

The German catalog value changed from
`Vollständiger Bericht: {name}. Full report separat anhängen oder teilen.` to
`Vollständiger Bericht: {name}. Bitte separat anhängen oder teilen.`.
`email.reportMissing` was already native German and is unchanged. The English
tests and the English `Full report:` copy are untouched.

## Review correction (2026-11-20)

The code/test review tightened the same contract; no Red assertion was removed,
skipped or loosened. Assertions that changed now pin the reviewed behaviour:

- The empty state is gated on `summary.scenarios.length === 0`, not on
  `counts.total`. A run with only unexecuted scenarios shows
  `format.noAttempts`, its unexecuted count and `0 scenarios with results`; the
  failed-scenarios section and the attempted-only pass-rate note are hidden only
  for a run without scenario rows. `empty.ndjson`, `empty-all-unexecuted.ndjson`
  and `empty-none.ndjson` are exercised as real fixtures.
- `--email` is rejected when it names an input directory or a path inside one
  (including through a junction or symlink), before any output is written.
- The mobile breakpoint moved from 600 px to 480 px, so 600 px keeps the 2 by 2
  metric grid and only narrower viewports stack. Status pills are separated by
  whitespace.
- The email uses a system sans-serif stack inline, `overflow-wrap:anywhere` on
  the heading, note and failed names, and caps displayed feature, scenario and
  report-name strings at 200 characters with an ellipsis.
- English email counts are grouped (`8,509 bytes`) and durations are human
  (`12 ms`, `12.3 s`, `1 min 5 s`, `1 h 2 min`) through email-local helpers;
  the report helpers are unchanged.
- Copy is recipient-facing: `No full report is attached.` /
  `Es ist kein vollständiger Bericht angehängt.`, a full pass-rate sentence,
  and `Attachments in the run` / `Anhänge im Lauf`.
- A hostile or unknown summary status falls back to the `unknown` label and
  colour, `reportName` is reduced with `path.basename`, an invalid `now` omits
  the generated date instead of throwing, and the `Email written to` line
  strips control characters.
- A failed email write without `--out` exits 1 with no stdout, no `--ci-out`
  file and no temporary file.

Test-contract note: the email duration assertions now expect the human form
(for example `12 ms`, `12.3 s`, `1 h 2 min`) rather than
`t.duration(...)`, and the byte assertion expects `8,509 bytes` rather than
`8509 bytes`. The report, JSON/CI and golden output are unchanged.
