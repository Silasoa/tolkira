# Design

## Safe-URL oracle

`src/render/format.ts` already has `safeHttpUrl(value)`, used by the CI and
attachment links. It removes the report's bidi-control set (U+202A–202E,
U+2066–2069), trims, and accepts only a URL whose parsed protocol is `http:` or
`https:`. The metadata link rule uses that function as its oracle and adds one
condition (internal tab/LF/CR), so there is still no second URL check.
`safeHttpUrl` itself stays unchanged for CI and attachment links.

The WHATWG parser normalizes some surprising inputs, and the spec records them:
`http:example.com` → `http://example.com/`, `https:\\example.com` →
`https://example.com/`, and `https://example.com/a b` →
`https://example.com/a%20b`. Values the parser rejects, and every non-http(s)
scheme, stay text. Tests encode this exact oracle rather than a hand-written
"looks like a URL" rule.

## Shared rendering rule

Add one helper in `src/render/format.ts`:

```ts
metadataValueHtml(value: string): string
```

- `safeHttpUrl(value)` is the linkability oracle; the tab/LF/CR check below can
  still reject a value it accepts.
- A safe URL renders as
  `<a href="<normalized URL>" rel="noopener noreferrer"><label></a>`, with both
  attributes/text escaped. The label is the value trimmed and stripped of the
  report's bidi-control set (U+202A–202E, U+2066–2069).
- A value with an internal tab, line feed or carriage return returns
  `escapeHtml(value)` without a link: the URL parser deletes those characters,
  so the normalized href could disagree with the visible label. This extra
  rejection lives in the metadata helper, not in `safeHttpUrl`.
- Anything else returns `escapeHtml(value)`, exactly as today.
- The helper coerces with `String(value ?? '')` before stripping, so an untyped
  JS caller that passes a number keeps the old `escapeHtml` text behavior
  instead of throwing. The empty-key/value filters in both surfaces use the
  same `String(value ?? '')` form, so that number reaches the helper as text
  instead of being dropped.

`metadataLine` in `src/render/report.ts` and the custom-metadata rows in
`src/render/details.ts` call the helper instead of `escapeHtml(value)`. Keys,
the empty-key/value filter and the surrounding markup stay unchanged.

`src/render/format.ts` already defines `safeHttpUrl` and imports
`stripBidiControls` and `escapeHtml`, so no module or dependency is added.
`RenderOptions.metadata` is `Record<string, string>`; the compatibility shim
stringifies its numbers and booleans before they reach this helper, so there is
no new numeric contract.

## Layout

The header's `.meta span` rule (`src/render/report.css:306`) already applies
`overflow-wrap: anywhere`, and the Details `dd` already has `min-width: 0;
overflow-wrap: anywhere`. The mandatory 320 px / 200 % e2e is the gate: if it
measures overflow, add `min-width: 0` to `.meta span` and
`overflow-wrap: anywhere` to `.meta a` in `src/render/report.css` and update the
goldens intentionally. Do not change the CSS preemptively; a global rule would
change every report's bytes for a case the existing rules may already cover.

`src/render/report.css` is the source; `src/render/styles.ts` is generated by
`scripts/build-styles.mjs` (`npm run styles`/`npm run assets`). Never edit the
generated file.

## Parity and integration (PIR + DXR)

- **Parity:** cucumber-html-reporter 7.2.0 and MCHR 4.6 print metadata as
  text; the official formatter links its structured CI job and GitHub commit
  (`CICommitLink`); Playwright links `ci`/`gitCommit` and ordinary metadata
  through its linkifier, with other metadata hidden until
  `?show-metadata-other`; Allure links only its dedicated issue/tms/link
  labels. This is a deliberate improvement, not a parity claim. There is no old
  link contract.
- **Surfaces:** the Report header and the Details custom-metadata panel. The
  Details header itself does not repeat custom metadata, so the panel is the
  second surface.
- **CLI and shim:** `--meta` fills `RenderOptions.metadata`; the compatibility
  shim flattens its `metadata` object to strings and calls the same renderer.
  Add a CLI test and a shim test so the claim is proven, not inferred.
- **Outputs:** the JSON summary has no metadata field; the email does not
  include custom metadata; CI text is built from the summary. Those bytes stay
  unchanged. The report HTML changes where a URL is linked; if the measured
  320 px gate needs the wrap fix, that small CSS change applies to every report
  and its goldens are updated intentionally. PDF derives from the report and may
  gain a link annotation, so it is not byte-stable.
- **Security:** only the metadata link rule creates an anchor; `javascript:`,
  `data:` and other schemes stay text. `rel="noopener
  noreferrer"` matches the CI links and also avoids leaking the local
  `file://` report path. The label is escaped and stripped of the report's
  bidi-control set (U+202A–202E, U+2066–2069). A value with
  an internal tab/LF/CR is rejected because the URL parser would delete those
  characters and the label could misstate the destination. The CSP is
  unchanged; the report fetches nothing.
- **Key naming:** use `CI run` in docs; a bare `CI` key would collide visually
  with the `meta.ci` label already shown in the same header.

## Host and integration gate

This is a report-shell change, so the Seed-Test row is relevant: it is the
compatibility-shim host and its report metadata is user-supplied. Re-run the
Seed-Test smoke with one URL metadata value (for example `CI run`) and record
the host, pin and result in `docs/DROP-IN-VALIDATION.md`, or record a written
reason why the focused shim/CLI tests cover it. Also run the Playwright host at
320/1440 for the header/Details layout if the Seed-Test report does not exercise
the long-URL case.

## Tests

- Header and Details each link a safe URL, with the normalized href, escaped
  label and `rel`; one run asserts both surfaces together.
- The three normalized forms above link; `javascript:`, `data:`, `ftp:`,
  scheme-less, malformed and plain values stay text.
- A URL with `&` and quotes is escaped correctly; a numeric value from a direct
  ESM call and a numeric shim value stay text.
- Empty key/value entries stay omitted.
- A long Actions URL does not overflow at 320 px and 200 % zoom; the JSON
  summary, CI text and email bytes are unchanged (compare existing outputs).

## Risks

- A metadata URL can point to an untrusted site; the user supplied it and the
  browser's normal link behaviour applies. No auto-fetch or preview is added.
- `http:example.com` and backslash forms become links because the existing
  oracle normalizes them; the spec and tests state this rather than pretending
  they are rejected.
- A backslash can make the label look like a different host:
  `https://evil.example\@good.example` is normalized to
  `https://evil.example/@good.example`, so the visible label does not literally
  match the href. The supplied value is shown and the generic browser-link risk
  is documented, not solved here.
- The report's bidi-control set is U+202A–202E and U+2066–2069. LRM (U+200E),
  RLM (U+200F), ALM (U+061C) and ZWSP (U+200B) are not stripped, so they can
  remain in a label; they do not change the href.
- Userinfo (`https://user@host/`) and IDN labels can look different from the
  normalized href; the full value is shown as the label and the generic
  browser-link risk is documented, not solved here.
- Values like `https://...` under a non-URL key (for example `Commit`) become
  links by design.
